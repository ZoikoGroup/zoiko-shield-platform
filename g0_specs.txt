# Document Control and Navigation

| **Control**              | **Value**                                                                                                                                                                                                                               |
|--------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Normative language**   | MUST = mandatory; SHOULD = expected unless an approved exception exists; MAY = optional.                                                                                                                                                |
| **Build scans without trustworthy builders**           | A compromised runner can fabricate results, replace dependencies or steal signing credentials.                  | Ephemeral isolated runners, pinned toolchains, bounded egress, short-lived identity and independent signing.                   |
| **SBOM produced as a compliance attachment**           | An unverified SBOM that is not bound to the artifact provides little trust.                                     | SBOM, provenance and policy results are generated during build and cryptographically bound to the exact digest.                |
| **Artifact rebuilt for each environment**              | Production may differ from what passed tests, invalidating assurance.                                           | Build once and promote by immutable digest with one bound release manifest.                                                    |
| **AI coding assistant outside SDLC controls**          | Sensitive input leakage, license contamination and insecure generated code can bypass normal ownership.         | Approved gateway/use cases, input minimization, human accountability, AI-use evidence and normal gates.                        |
| **Emergency path as pipeline bypass**                  | Urgency can create unaudited privilege and unreconciled production drift.                                       | Compressed but controlled emergency workflow with independent review, signed manifest, rollback and post-event reconciliation. |
| **Dependency automation optimized only for freshness** | Automated upgrades may introduce malicious, incompatible or license-prohibited code.                            | Risk-based dependency intake, internal mirrors, policy, sandboxing, owner/expiry and staged update evidence.                   |
| **Deployment approval separated from customer impact** | Technically healthy release may breach contract, residency, evidence, AI disclosure or service obligation.      | Release manifest includes customer/tenant scope, obligations, communication and claim impact.                                  |
| **Remote-team control based on trust statements**      | Shared access or broad production privileges defeat accountability.                                             | Individual identities, managed devices, least privilege, authorship/review/release separation and JIT production custody.      |

# Document Control and Navigation

| **Control**                    | **Value**                                                                                                                                                                        |
|--------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Normative language**         | MUST = mandatory; SHOULD = expected unless an approved exception exists; MAY = optional.                                                                                         |
| **Security mixed with infrastructure and CI/CD detail**  | Creates duplication with Documents 12-14 and leaves ownership unclear.                                  | This document defines platform-security invariants and handoffs; later documents specify deployment, pipeline and test implementation. |
| **Perimeter-centric design**                             | A multi-tenant remote-managed security platform is not protected by network location.                   | Continuous identity, device, workload, tenant, purpose and state decisions at every boundary.                                          |
| **Threat model treated as a one-time workshop**          | Drifts immediately as connectors, AI, response actions and cloud services change.                       | Threat models are versioned engineering inputs with automated fitness tests and change triggers.                                       |
| **Cryptography reduced to “encrypt at rest/in transit”** | Omits key separation, signing, independent verification, rotation, compromise and migration.            | Purpose-specific trust hierarchy, per-tenant context, short-lived identity and crypto-agility contracts.                               |
| **Vulnerability priority based only on CVSS**            | Under-prioritizes exposed, exploited or authority-bearing paths and over-prioritizes unreachable noise. | Risk model includes reachability, exploit maturity, privilege, tenant blast radius, action authority and active exploitation.          |
| **Supply-chain assurance ends at SBOM**                  | An SBOM does not prove source, build process, artifact integrity or approved deployment.                | Protected source, isolated build, provenance, signing, admission verification, staged release and revocation chain.                    |
| **AI security isolated in the AI document**              | Prompt injection and tool abuse cross into core, evidence and response systems.                         | AI security becomes a platform-security boundary with target-side authorization and kill controls.                                     |
| **Remote-team controls framed as distrust**              | Creates adversarial culture without improving security.                                                 | Compartmentalization, least privilege, managed endpoints, segregation of duties and auditable JIT access.                              |
| **Pen test used as final gate**                          | Late testing cannot compensate for missing design invariants or automation.                             | Design review, automated negative testing, continuous verification and independent adversarial assessment form one assurance stack.    |
| **Security logs treated as operational logs**            | May be mutable, incomplete, unscoped or unusable for incident reconstruction.                           | Material security events are separately governed, reconciled and evidence-preserved.                                                   |
| **Recovery defined as service availability**             | A compromised platform can return online with broken trust.                                             | Recovery requires identity, keys, tenant isolation, evidence, action authority and supply-chain integrity to be re-established.        |

| **Report**    | Unauthorized access, accidental forwarding, lost device, suspicious export, public AI use, customer data exposure, access after role end or bypass attempt. |
| **Contain**   | Suspend access, revoke sessions/tokens, block sharing, isolate device or disable provider/integration.                                                      |
| **Preserve**  | Retain repository, IAM, DLP, endpoint, ticket, AI-gateway and communication evidence.                                                                       |
| **Assess**    | Classify information, recipients, geography, customer/contract impact and exploitation risk.                                                                |
| **Notify**    | Security, document owner, Legal/Privacy, People and affected customer/regulator owners as required.                                                         |
| **Remediate** | Recover or delete copies where lawful, rotate secrets if exposed, correct access policy and update controls.                                                |
| **Review**    | Root cause, control failure, disciplinary/process separation, lessons learned and CAPA.                                                                     |
| **Close**     | Evidence complete; access restored or terminated; claims/notifications reconciled.                                                                          |

| **FAIR PROCESS**                                                                                                                                                                                                                   |
|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| The control system records objective access and handling events. It must not presume malicious intent. Security containment, factual investigation, employment decisions and legal conclusions remain separate governed processes. |

*Figure 7. Role change and offboarding control chain.*

| **Trigger**                   | **Required control**                                                                                                                                |
|-------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------|
| **High-risk / involuntary**   | Immediately revoke EC-3, privileged, production, vault and active sessions; complete remaining access removal within the approved emergency target. |
| **Normal termination**        | Remove all access by end of final working period; pre-stage ownership transfer and session/token revocation.                                        |
| **Role or workstream change** | Recalculate access intersection; remove prior bundles before adding new ones where SoD risk exists.                                                 |
| **Contractor end**            | Automatic expiry from authoritative contract date; sponsor certifies extension before renewal.                                                      |
| **Subcontractor**             | Prime supplier remains accountable; no downstream access without prior identity, contract and security approval.                                    |
| **Leave / suspension**        | Suspend or narrow access based on risk and business need; retain evidence and avoid unnecessary personal-data processing.                           |

## 19.1 Closure checklist

- Identity, sessions, tokens and MFA factors resolved.

- Document, code, issue tracker, CI/CD, cloud, database, observability and vault access removed.

- Managed device returned, locked or securely wiped under policy.

- Local controlled copies and offline exports addressed where technically and legally possible.

## **7.2 Evidence-Based Extraction Criteria**

1\. A module’s sustained scaling profile distorts shield-core capacity by at least 30%, or causes two unrelated rollback events in a quarter.

2\. A materially different release cadence causes measurable queueing, safety or availability harm that cannot be solved through module flags or staged delivery.

3\. A contracted isolation class requires physical separation of the module’s data, keys or compute.

4\. A dedicated team owns the module end-to-end and measured coordination cost exceeds the operational cost of separation.

5\. A crown-jewel threat model requires independent compromise containment, as already established for the four satellites.
